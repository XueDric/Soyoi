# 战斗与素材系统修复记录

## 保留的游戏规则

**素材继承承载牌的目标。** 拼豆色包、吧唧底坯、流麻胶液等装在自身技能牌上时，仍会对玩家造成伤害或施加易伤、虚弱。这是有意保留的特性，不会自动改选敌人；自身素材伤害照常受格挡和状态影响。

## 已修复

- 运行时卡牌、素材组件及素材捆按实例区分；移动牌堆不会误删同名牌，也不会重复添加同一实例。
- 出牌先移出手牌，在卡牌和素材都结算完成后进入弃牌/消耗堆或返回手牌。满手打抽牌牌会先释放一个位置，结算中的牌不能被自己抽回。
- 出牌统一校验战斗阶段、存活状态、手牌归属、能量、不可打出关键字及目标。鼠标、数字键与脚本不能绕过检查。
- 卡牌结算后由核心统一裁定胜负；死亡立即停止剩余效果，不能再出牌治疗复活。双方同时死亡按失败处理。
- 敌人的防御格挡保留到下一玩家回合，到下一敌方回合开始才清除。敌人意图由核心随回合更新，不依赖 UI。
- 自封袋保留、素材常驻加费与本回合临时状态分开；加工立即同步，跨回合仍有效，替换素材后移除对应效果。回合重置覆盖四个牌堆。
- 活力仅增强下一张攻击牌，包括该牌的所有伤害段及附着素材伤害，结算后消耗；未使用的活力可跨回合保留。
- 荆棘按攻击触发反伤，即使伤害被格挡吸收也触发；反伤不再次触发荆棘，自身攻击不反伤自身。攻击者被反伤击败后停止剩余连击。
- 临时负力量可实际降低伤害，回合末恢复；界面显示负数状态。中毒直接扣血，不被格挡抵消。
- “每回合一次”计数随回合重置；“本场首次”独立于每回合标记。
- 素材返手在结算结束后生效；消耗优先于返手，手牌满时返手进入弃牌堆。
- 抽牌堆末尾统一为堆顶，弃牌置顶的牌会在下一次抽牌时抽到。
- 两份同名素材可以分别存储并合料；同一组件重复存储幂等。无效加工槽位不会丢失素材，加工成功后素材 Token 进入消耗堆。
- 素材 Token 可以在 UI 中显示，不再错误请求其承载槽；满手生成素材时进入弃牌堆。
- 多张伤口保持独立，升级伤口仍不可打出。

## 接口注意事项

直接写测试/演示脚本时，必须先 `start_combat()`，或显式构造有效的 `phase="player"` 测试状态，并将要打出的实例放入手牌。

自身技能牌应传入玩家或省略目标，单体攻击应传入本场存活敌人或省略目标使用默认敌人。原有 `card_showcase`、`smoke_test` 已适配。

`CardSpec` 仍是静态数据定义，运行时 `Card` 不再按卡面字段相等。比较牌种请用 `card_id`；比较具体哪一张牌请用实例身份。

## 验证

```powershell
python -m unittest discover -s tests
python -m scripts.smoke_test
python -m scripts.card_showcase
```

本次验证共 **57 项测试通过**（原有 17 项，新增 40 项）。新增测试位于 `tests/test_regressions.py`，包含 100 局固定种子压力测试，逐次检查：

- 牌堆实例集合保持不变；同一实例只出现一次；
- 不超过手牌上限；生命与能量保持合法范围；
- 战斗结束后操作无法改变战斗状态；
- 默认 Demo 第二回合“防御”的原始复现路径；
- 技能牌素材作用于玩家的保留规则。

UI 检查使用 pygame 的 dummy 视频驱动执行绘制及交互逻辑，不替代真实窗口下的长时间人工试玩。
