# 程序说明

---

## 1. 主要模块

```
main.py              入口：决定开哪个窗口          ← 先看这个
tkinter_ui.py        造牌的界面(Tkinter)
pygame_ui.py         打牌的界面(Pygame)
card_creator.py      数据处理：检查，存 JSON，交给战斗框架
core/ combat/ soyoi/ content/    战斗框架：回合，能量，伤害结算，素材系统
```

| 文件 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| `main.py` | 解析命令行参数，把 `--battle` / `--demo` / `--list` 分给对应的模块 | 不写界面，不做检查 |
| `tkinter_ui.py` | 画表单，读输入框，把提示显示在出错那一行，调保存 | **不算数值，不写文件** |
| `pygame_ui.py` | 画血量/手牌/敌人，把鼠标点击翻译成“我要出这张牌” | **不改血量，不算伤害** |
| `card_creator.py` | 检查输入，生成卡面文字，读写 JSON，拼起始牌组 | 不 import tkinter，也不 import pygame |
| 战斗框架 | 回合流程，能量，伤害与格挡结算，素材系统，胜负判定 | 不知道界面长什么样 |

界面代码只负责收集输入和显示状态，规则层负责修改战斗数据。比如换配色只需要改 `pygame_ui.py`，伤害公式集中在 `combat/resolver.py`.

## 2. 从填表到出牌

```
① 玩家在 tkinter_ui.py 的表单里填:名称"重击",费用 2,效果"造成伤害 12"
                │
                │  collect_fields() 把输入框读成字符串字典
                ▼
② card_creator.make_card_record() 检查并整理
                │   · 费用能不能转成整数？在 0~3 之间吗？
                │   · 效果认不认识？数值在范围内吗？
                │   · 有错 -> 返回 {"cost": "费用要填整数…"},界面显示在那一行
                ▼
   一条卡牌记录(dict)
   {"card_id": "user_2026…", "title": "重击", "cost": 2,
    "card_type": "attack", "target": "enemy",
    "text": "造成12点伤害.", "effects": [{"op":"damage","value":12,"hits":1}]}
                │
                │  save_card() 写文件
                ▼
③ user_cards/user_2026….json          ← 一张卡 = 一个文件
   user_cards/art/<编号>.png           ← 这张卡的卡面图片(玩家自己挑的，可选)
   user_decks/deck_xxx.json            ← 一个卡组 = 一个文件:{"编号": 份数}
   user_decks/selected.json            ← 只记着"对局用哪副卡组"
                │
                │  战斗开始时 load_cards() + resolve_deck()
                ▼
④ card_creator.make_card_spec() 把记录变成战斗框架认识的 CardSpec
                │
                │  deck_specs(卡组) 按编号把牌一张张取出来(缺的跳过)
                ▼
⑤ 一副完整的牌组 -> Player 的抽牌堆
                │
                │  pygame_ui.py 只负责画出来
                ▼
⑥ 玩家点击"重击" -> combat.play_card(card, enemy)
                │
                ▼
⑦ combat/resolver.py 按效果枚举结算：造成 12 点伤害，扣 2 点能量，进弃牌堆
```

第 ④ 步之后，自制卡和系统卡都变成 `CardSpec`，再交给同一个结算器处理。因此它们使用同一套护盾，易伤和力量规则。

**卡组是怎么回事**：以前只有一份“测试牌组”(`user_cards/test_deck.json`),
现在改成可以建多副，各自取名的卡组：

```
① 造牌端点"新建卡组",起个名字
                ▼
② new_deck()：底子就是 4 张打击 + 4 张防御
                ▼
③ 造牌 → "保存卡牌"会顺手把这张牌加进当前卡组(也可以点"加入该卡组")
   "保存卡组"把改动存盘;"另存为"留着原来那副再存一份新的
                ▼
④ set_selected_deck()：下拉框里选中的那副，就是战斗端要用的牌组
                ▼
⑤ 战斗端 resolve_deck() -> deck_specs() -> 直接拿这副牌开打
   (示例卡组内置只读，改动落在玩家自己那副卡组上)
```

老的 `user_cards/test_deck.json` 第一次加载时自动升级成“我的卡组”，
老文件改名成 `.json.migrated`(卡组文件里存着 4 打击 + 4 防御 的底子)。

素材牌走的是同一条流水线，只是第 ④ 步换成 `make_material_spec()`,
造出来的是 `MaterialCardSpec` -> `MaterialCardBase`(素材牌)：

```
① 造牌端把类型选成"素材":效果"造成伤害 3",类别"普通"
                ▼
② make_card_record()：费用锁定 0，目标锁定自己，关键字留空
                ▼
③ user_cards/xxx.json 里 card_type = "material",effects 用 material_* 效果
                ▼
④ make_material_spec() -> MaterialCardSpec -> MaterialCardBase(不能打出，回合结束不掉)
                ▼
⑤ 跟着卡组进对局，被抽到手牌里
                ▼
⑥ 玩家点这张素材牌 -> 再点一张手牌 -> equip_from_hand() 把它装上去(3 槽，满了合料)
                ▼
⑦ 那张牌下次打出时，material_effect_resolver.py 才结算素材效果
```

## 3. 代码位置

### 3.1 `main.py` —— 入口，只做分发

```python
if args.check:
    return run_check(args)          # 自检：数据 -> 战斗能不能跑通
if args.battle or args.screenshot:
    return run_battle(args)         # 开战斗界面
return run_creator(args)            # 默认：开造牌界面
```

不带参数运行就是造牌界面——这是这个项目的主线功能。
### 3.2 `card_creator.py` —— 数据处理

按从上到下的顺序分成六段，每段之间用注释分隔：

| 段落 | 内容 | 关键函数 |
| --- | --- | --- |
| 一，常量表 | 卡牌能填什么：10 种效果(英文键 -> 枚举 / 中文名 / 数值范围 / 卡面文字模板)；素材牌另有一套表 | `EFFECTS`,`EFFECT_LABELS`,`VALUE_LIMITS`,`EFFECT_TEXTS`,`MATERIAL_EFFECTS` |
| 二，输入检查 | 把“玩家乱填”变成人话提示 | `check_number`,`check_effects` |
| 三，整理记录 | 表单 -> 一条卡牌记录，错误按字段名返回 | `make_card_record`,`describe_effects` |
| 四，JSON 读写 | 存一张卡，读全部卡；卡组的新建 / 存取 / 选中 | `save_card`,`load_cards`,`new_deck`,`save_deck`,`set_selected_deck` |
| 五，接入战斗 | 记录 -> `CardSpec`(素材牌 -> `MaterialCardSpec`)-> 牌组 | `make_card_spec`,`make_material_spec`,`resolve_deck`,`deck_specs` |
| 六，命令行 | 不开窗口也能造牌，看牌 | `list_cards`,`create_sample` |

这一层用几张表描述效果。增加一种效果时，需要把它接到效果枚举，标签，数值范围和卡面文字：

```python
EFFECTS["poison"] = RewardEffectOperation.POISON       # 接上战斗框架
EFFECT_LABELS["poison"] = "施加中毒"                    # 界面多一个选项
VALUE_LIMITS["poison"] = (1, 9)                        # 数值范围
EFFECT_TEXTS["poison"] = "给予{value}层中毒."          # 卡面文字
```

**中文只出现在两张“标签表”里**(`EFFECT_LABELS` / `MATERIAL_EFFECT_LABELS`),
代码里的键，判断，分支全部用英文(`"damage"`,`"material_damage"` 这种)，
所以改文案和改逻辑互不影响。
素材牌是同一套写法，只是表格换成了 `MATERIAL_EFFECT_*` 那几张：
每条素材效果自带“作用目标”和“触发时机”，数据在表里，结算器只认枚举。
界面上给玩家看的提示文字(报错，状态栏，战斗界面消息)仍然是中文 —— 那是产品本身的语言，
分界线是：**逻辑不认识中文，文案不参与判断**.

### 3.3 `tkinter_ui.py` —— 造牌的界面

```
CardCreatorApp           主窗口
├── ① 卡牌信息区         名称，费用，类型，目标，稀有度，关键字
├── ② 效果区             EffectRow 列表，每行 = 效果下拉框 + 数值 + 段数 + 删除
├── ③ 卡面预览           实时显示"这张牌会变成什么文字"
└── ④ 卡组面板           选/新建卡组 + 加入该卡组 + 保存卡组 + 删除卡组
    ⑤ 已保存卡牌列表     卡片列表 + 载入表单 + 删除卡牌
```

三处设计：

1. **读出来都是字符串**.`collect_fields()` 不做任何转换，
   `"2"` 就交给 `card_creator.check_number` 去转——转换和检查放在一起，
   报错信息才能说得清“费用要填整数”。
2. **错误显示在出错的那一行**。校验返回的是 `{"effect_1": "…"}` 这样的字典，
   界面按索引把提示贴到对应的效果行下面。
3. **两种保存行为**：新建时同名自动加 `-2` 后缀(原文件保留)；
   从列表里“载入表单”再保存才覆盖原文件(这时玩家是在改数值)。

类型选到“素材”时，界面会整套换一遍：效果行换成素材效果(`EffectRow.set_kind`),
第三个下拉框从“稀有度”变成“素材类别”(一次性/普通/永久/诅咒)，
费用与关键字锁上 —— 素材牌不花能量，也不能打出。

“卡面图片”那一行则是不分类型的：普通牌和素材牌都能挂一张自己的插画，
选了图保存后，创作端预览和战斗端的卡面都会用它(见 3.8).

类别参与结算：`make_material_spec()` 把“一次性”翻译成素材效果的 `consumes_component`,
这条素材在承载牌打出，效果结算完之后就从槽位消失；普通 / 永久 / 诅咒素材一直留着。
(类别是 `one_shot` 的那三种素材，都带同样的消耗标记。)

### 3.4 `pygame_ui.py` —— 打牌的界面

| 部分 | 作用 |
| --- | --- |
| `PygameCombatDemo.__init__` | 开窗口，加载背景图和角色图(**只在启动时加载一次**) |
| `reset_combat()` | 组牌组，造敌人，开始一局(这里会去读 `user_cards/`) |
| `run()` 主循环 | 事件 → 更新 → 绘制 → 交给玩家看，60 FPS |
| `draw_*()` 系列 | 血量条，手牌，牌堆，状态图标，胜负浮层 |
| `handle_click()` | 点击只做一件事：把“点了哪张牌/哪个敌人”翻译成指令 |
| `begin_material_choice()` / `choose_material_target()` | 素材牌的两步操作：先点素材牌，再点要加工的那张手牌 |

**这个文件一行都不改数值**。它调用 `combat.play_card(card, target)`,
然后重新读战斗状态来画。所以界面上显示的伤害和规则算出来的永远一致——
如果界面自己写 `enemy.hp -= 12`，一旦有护盾，易伤，荆棘，两边立刻对不上。

素材同理：界面把“点了哪张素材牌，点了哪张手牌”交给
`soyoi.material_runtime.equip_from_hand()`，装不装得上，槽满不满，要不要合料，
全是框架说了算，界面只把返回的提示文字显示出来。

### 3.5 战斗框架 —— `core/` + `combat/` + `soyoi/` + `content/`

| 目录 | 内容 |
| --- | --- |
| `core/cards.py` | 卡牌数据类 `Card`/`CardSpec` + 所有枚举(类型，目标，效果，关键字) |
| `core/pile.py` | 抽牌堆/手牌/弃牌堆/消耗堆，洗牌与移动 |
| `core/creature.py` `player.py` `enemy.py` | 生命，格挡，状态；敌人的意图与 `brain` 钩子 |
| `core/combat.py` | 一局战斗的状态机：开始回合，出牌校验，结束回合，判定胜负 |
| `combat/resolver.py` | **结算器**：把一张牌的效果列表逐条执行 |
| `soyoi/` | 素材系统(素材牌，三槽加工，承载牌触发)，本项目的特色系统 |
| `soyoi/material_runtime.py` | 素材盒与加工入口：`store()` 把素材变成手牌，`equip_from_hand()` 才是“装上去” |
| `content/enemies.py` | **五只敌人**：各自的套路，台词，外观 |
| `content/` | 实际内容：角色“所依”，40 张奖励牌，6 种素材 |

**素材分两步**：打出“生成素材”的牌把素材**发到手牌**,
装到哪张牌上由玩家点两次决定(素材牌是 Token 技能牌，不能打出，回合结束也不掉)。
这条规则只写在 `equip_from_hand()` 一个函数里，界面和卡牌效果都走它。

### 3.6 `content/enemies.py` —— 五只敌人与三种意图

#### 意图只有三种

照着原游戏里最常见的三类怪物行为简化，敌人下回合要做什么，
玩家出手前就能看到(这是这类敌人好玩的核心)：

| 意图 | 做什么 | 原游戏里对应的怪 |
| --- | --- | --- |
| `ATTACK` 攻击 | 打你(可多段，可附带效果) | 颚虫啃咬，小偷扒手，哨卫连击 |
| `DEFEND` 防御 | 给自己套格挡 | 颚虫硬化，强盗逃跑 |
| `BUFF` 强化 | 给自己加力量，越打越痛 | 邪教徒的仪式 |

原游戏里“上毒，塞伤口，偷东西”这类花样，做成挂在 `ATTACK` 上的附加选项：

所以 `Intent` 就四个字段加两个可选参数：动作，数值，段数，说明文本
(+ 附带状态 + 塞废牌)。

#### 五只怪

| 敌人 | 生命 | 套路(只用三种意图) | 玩家该怎么应对 |
| --- | --- | --- | --- |
| 颚虫 `jaw_worm` | 44 | 啃咬 11 → 硬化(防御 6)→ 甩尾 7 | 它硬化那回合正好攒牌 |
| 狂热教徒 `cultist` | 52 | 第 1 回合“仪式”(强化 +3)，之后一直鞭击 6 | 必须速杀，拖越久越痛 |
| 摸金校尉 `looter` | 46 | 偷窃 10 → 扒手 5×2 → 逃跑(防御 18)→ 烟雾弹(攻击 4 + 虚弱) | 逃跑回合别浪费输出 |
| 铁皮哨卫 `sentry` | 60 | 蓄力(强化)→ 重击 16 → 装甲(防御 8)；血量过半后改成过载连击 8×4 | 趁它重击前把血打下去 |
| 废料巨像 `scrap_colossus` | 140 | 一阶段挥砸 12 / 上发条 / 铁壳；二阶段碾压 6×3，灌铁屑 4×2(顺带塞牌)，重锤 18 | 算好阶段血量，备好格挡 |

写一只怪就两步 —— 挑意图 + 配长相：

```python
class Cultist(SoyoiEnemy):
    appearance = {"shape": "robe", "color": (78, 66, 102), "accent": (218, 91, 75)}

    def __init__(self):
        super().__init__("邪教徒", 52, flavor="仪式开始了.")

    def choose_intent(self, combat):
        if self.turn == 1:
            return self.buff(3, label="仪式 力量+3")     # attack / defend / buff 三个小工具
        return self.attack(6, label="鞭击 6")
```

`SoyoiEnemy` 把 `choose_intent` 挂到战斗框架的 `brain` 钩子上，
框架每回合调一次(见 `core/combat.py` 的 `next_enemy_intents`).
不想写类也行：给 `act_pattern` 一个意图列表，框架按回合取模循环。


### 3.7 `tkinter_ui.py` 里的卡面预览

造牌界面的第 ③ 块不是一行提示文字，而是一块**画布(`CardPreview`)**:
费用圆圈，类型配色，卡面文字，关键字标签，稀有度小星都实时画出来。
用画布画卡面：造牌的重点是看到成品，而且这样和战斗界面里卡牌的样子保持一致。
填错了就在这块画布上显示第一处错误，右侧小字列出全部要改的地方。

### 3.8 卡面图片：从挑选到进对局

| 环节 | 代码 | 做什么 |
| --- | --- | --- |
| 挑图 | `CardCreatorApp.choose_art()` | 文件对话框(只列图片后缀)→ 当场读一次，读不出来就提示换一张 |
| 记住它 | `_art_choice` / `_art_saved` | 刚挑的还没保存；已保存的是记录里的相对路径 |
| 预览 | `load_art_image()` + `CardPreview.show_card(record, art_path)` | 先让 Tk 自己读(PNG / GIF 是它自带的)；jpg / webp / bmp 交给 pygame 解码后再转给 Tk，所以不用装额外的图像库 |
| 落盘 | `cc.save_card(..., art_source=...)` → `cc.save_card_art()` | 复制进 `user_cards/art/<编号>.<后缀>`，记录里写 `"art": "art/<编号>.png"` |
| 校验 | `cc.check_art()` / `cc.is_image_file()` | 只认 `art/` 下的文件名；后缀对但文件头不对(改名的假图)也拒收 |
| 清理 | `cc.remove_card_art()` | 换图，点“清除”保存，删掉卡牌时都删干净，不留孤儿文件 |
| 战斗端 | `PygameCombatDemo.card_art_for(card)` | 玩家自己设的图优先，其次按编号找到的卡面，都没有就画占位卡面 |

图片**复制**而不记原图路径，是这样整份 `user_cards/` 目录可以直接备份，发给同学；
JSON 里也不会出现别人电脑上的绝对路径。

## 4. 模块之间的约定

1. **界面只发指令，不改数据。**
   点击 -> `combat.play_card()` -> 结算器改数据。界面只负责显示。

2. **数据只有一份权威格式。**
   自制卡是“一条记录一个 JSON 文件”。手改过的 JSON 在读回来时会用
   跟表单一样的规则**再检查一遍**，把伤害改成 99999 也进不了游戏。

3. **坏数据跳过，不影响其他内容。**
   目录里有一个坏文件，`load_cards()` 会把它列进错误提示然后跳过。
